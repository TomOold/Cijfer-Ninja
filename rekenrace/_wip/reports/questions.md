# Report: vragen (RR.Questions)

## Summary
RR.Questions is finished as a part file (about 1200 lines, ASCII only: all U+2212, U+00D7 and accents are written as \u escapes) with a node:test suite of 30 tests, all passing in about 50 s. Everything in BRIEF 5.1 is implemented: KINDS, FOCI, make, series, fromKey and check, with the exact Question shape (key, kind, text, answer, hint, explain, formula) and nothing else exported. The ramp is data-driven. Named banks of number shapes (AD, SB, TM, DV and story banks ST) are composed into one PROFILE row per (grade 3..6, level 1..8) through `row(mix, add, sub, times, div, story, gapOps, gapPos)`, so retuning means editing one line. Hints and explanations come from per-operation method lists with the Dutch rekenmethode ideas: dubbelsom, 10 vol maken, via het tiental, splitsen, rijgen, compenseren, aanvullen, tafel van 6 = 5 + 1 keer erbij, 9 = 10 min 1 keer, verdubbelen and halveren, delen als omgekeerde van keer, nullen erachter. A method is picked per sum from a hash of its key, so hint and explanation always describe the same method and fromKey rebuilds a sum exactly, stories included. A bridging explanation appears only when the sum really bridges. Explanations are packed into at most 3 short lines. There are 29 story templates built from 11 shapes, from one-step stories to two-step ones, each with a plausible maximum number. Series draw each place from a small pool at a rising difficulty quantile, start with the easiest plain sum, never open with a gap sum or a story, avoid three equal kinds in a row, keep keys and answers distinct and weave in up to 2 valid repeat keys at places 2 to 5. A mutation run (12 deliberate bugs, such as a leaking hint, an inexact division, a wrong gap solution, a wrong check() or a repeat in first place) was caught by the suite every time.

## Limitations
- Distinct answers inside a series are only guaranteed while the space of sums has at least `count` different answers. That holds for count 10 in every grade x level x focus and for table 1..10; the 'times' focus at groep 3 level 1 only just reaches it. With a smaller space (for example count 20 on one table) the engine repeats an answer, but never a key, and only after exhausting the strict options.
- In groep 3 levels 5 to 8 every number stays within 100, so a magnitude-only measure is flat there. The ramp comes from carries and borrows, tables 2/5/10, gap sums and stories. The ramp test therefore uses an explicit rank (log10 of the biggest number, a bonus per kind, a bonus for a carry or borrow) with a tolerance of 0.03 between consecutive levels; a pure operand-size test would not pass in groep 3 levels 6 to 8 or groep 6 levels 7 to 8.
- Hints and explanations are bare Dutch lines. The UI adds the tone ('Nog niet helemaal.' etc.) around them. The hint never contains the answer as a number. When a numeric hint would leak (for example 1 x 10) it falls back to a wording with number words ('tafel van tien') or a number-free line.
- Story numbers at the highest tiers can be large and playful (for example '4957 schelpen'). Each template has a cap so that boats, cows, children per boat and the like never get absurd numbers, but schelpen, tulpen, appels and similar can reach 4 digits in groep 6.
- fromKey only accepts canonical keys (no leading zeros, no whitespace, exact operator characters) and rejects gap sums whose result is 0. A sum with answer 0 such as sub:5-5 is still accepted as a plain sub.
- A table restriction on the division kind means the table is the divisor. For gap sums on a table the table number may be the hidden number (answer = table), as in '? x 8 = 56' for table 7.
- series(opts, count) caps count at 200, returns [] for count <= 0 or NaN and defaults to 10 when count is undefined.
- The suite runs about 50 s because it covers 192 grade x level x focus configurations with 300 seeds each. The SEEDS constant at the top of the test file sets the seed count if that ever needs trimming.
- parts/pure-sommen.js is now the source of truth. The chunk files c1..c7.js and build.py in scratchpad/work only produced it (concatenation plus conversion of non-ASCII to \u escapes). Edit the part file directly, and keep it ASCII only.
- The engine uses only ES2015+ syntax, avoids regex lookbehind (older Safari) and avoids ?., ??, ||= and .at(), so it parses everywhere the rest of the game does.

API DETAILS. make(opts, rng) returns one question; series(opts, count = 10, rng) returns the series. rng defaults to RR.Rng.random(). Unknown or odd opts are clamped (grade 3..6, level 1..8, bad focus becomes 'mix', table outside 1..10 is ignored, numeric strings are accepted).
Key formats: add:47+36, sub:83-47, times:7x8, div:56:8 (dividend:divisor), gap:add:24+?=51, gap:sub:?-8=15, gap:sub:30-?=12, gap:times:7x?=56, gap:div:48:?=6, gap:div:?:8=7, story:eieren:6:8 and story:kisten:30:12:8 (ids are lowercase letters; the numbers equal the numbers in the text, in order).
Text: plain sums are '47 + 36 = ?'; gap sums put '?' in place of one number ('? : 8 = 7'); stories are a statement, '\n', then a 'Hoeveel ...?' line. Explanations use at most 3 lines separated by '\n'; hints are one line.

FOCUS AND TABLE SEMANTICS (also documented in the module header). focus add, sub and story give exactly that kind. focus times gives kind times plus gap sums that hide a factor (about one in three sums); focus div gives kind div plus gap sums with ':'. In those gap sums the hidden number may be in either position. With table set: focus times/div restrict to that table; focus mix + table turns the series into times + div + gap(x, :) of that table; add/sub ignore the table; focus story with table >= 2 gives x and : stories using that table as the 'per group' number (table 1 is ignored there because story numbers must be >= 2). repeat keys are only woven in when they fit the focus (and touch the table when one is set).

One step, ':': verdeel, dozen, tochtje, plantrijen, koekjes. Two step: bakken (a x b + c), kratten (a x b - c), haven (a + b - c), weekschelpen (a + b + c), broodjes (a - b - c), kisten ((a x b) : c), knikkers (a : b + c). Themes: tulips, mill, beach, polder, canal, harbour, ice rink, plus the heroes' names Eef, Sien, Bram and Oeke. All numbers in a story are >= 2. Tiers 0..6 per shape: 0 within 20, 1 within 100, 2 to about 150, 3 within 1000, 4 to about 1500 or 2-digit x 1-digit, 5 thousands, 6 2-digit x 2-digit.
